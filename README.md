# astrbot_plugin_funhub · 龟龟乐园

群聊签到与龟龟币。日常签到攒币，连签满 7 天 / 30 天各有一档可重复的周期奖励；
支持把老插件 [astrbot_plugin_LevelUpPvp](https://github.com/QuanWenG/astrbot_plugin_LevelUpPvp)
的等级与签到记录整体搬过来，并按历史记录补发龟龟币。

相对老插件，这里刻意只保留「签到 / 连签 / 等级展示 / 排行」，去掉了属性、经验、
战斗、副本、装备与工坊。

## 指令

指令走 AstrBot 的唤醒机制：**必须用唤醒前缀**（全局 `wake_prefix`，默认 `/`），
或者 `@机器人` / `@全体` / 引用机器人消息后再发。群里直接发裸 `签到` 不会触发。

| 指令 | 别名 | 说明 |
| --- | --- | --- |
| `/签到` | `/打卡`、`/每日签到` | 领取当天龟龟币，累计连签 |
| `/面板` | `/我的信息`、`/我的面板` | 等级、连签、累计签到、龟龟币、本群排名 |
| `/排行` | `/排行榜` | 本群排行，默认按等级；`/排行 币` 按龟龟币存款；`/排行 @某人` 查该成员名次 |
| `/决斗` | `/挑战`、`/艾斯比`、`/啥比` | 和 @ 到的人掷一把定胜负，输家掉龟龟币（机器人是管理员时还会被禁言） |
| `/轮盘` | `/转盘`（`/龟龟轮盘` 也认） | 开一局左轮轮盘：6 个弹槽 1 颗子弹 |
| `/开枪` | — | 扣一次扳机：空枪发币，中弹扣币并禁言 |
| `/救一下` | `/解禁` | 把中弹被禁言的人捞出来 |
| `/补一枪` | `/补枪` | 给中弹被禁言的人追加一次禁言（有概率卡壳 / 反噬） |

指令名集中在 `funhub/commands.py` 的 `COMMAND_ALIASES`，想避让别的插件重名改这一处即可。

#### 名字前面多个「龟龟」也认

插件叫龟龟乐园、币叫龟龟币，所以顺手打成 `/龟龟轮盘` 很正常 —— 插件会忽略开头的
`龟龟` 再匹配（`/龟龟轮盘` = `/轮盘`，`/龟龟排行 币` = `/排行 币`）。指令名本身保持
朴素功能名，不带「龟龟」。

指令名写错、但对得上某条指令的开头（`/轮盘啦`、`/排行榜啦`）时，插件会回一句
`指令是 /轮盘`，而不是一声不吭 —— 「没反应」最容易被当成插件坏了。判定收得很紧：
指令名必须在最前面、后面最多再跟 4 个字，所以闲聊里提一句「这个面板挺好看」不会被纠正。

`@机器人 指令` 的两种平台形态都支持：

* 平台把 @ 从文本里去掉时（aiocqhttp）走 AstrBot 的命令过滤器；
* @ 标记留在文本里、甚至不给 `At` 组件时（QQ 官方机器人的常见形态）走插件自己的
  @ 唤醒通道 —— 先去掉 @ 标记再匹配。

两条路径共用同一套实现，同一条消息只会处理一次、不会回两次。白名单外的唤醒指令
不回复，但会在日志里留一条「收到指令但群不在白名单」，免得看起来像插件坏了。

#### 老插件的便捷唤起词

`艾斯比` / `啥比` 沿用老插件的语义：**它们自己就是唤起词**，只要 @ 到对手就能开打，
不必再 @ 机器人。而且和语序无关、**出现在句子任何位置都算**（老插件就是
`any(word in message ...)`），所以这些都行：

```
@对手 艾斯比          艾斯比 @对手          你个艾斯比吧你 @对手
来决斗啊 @对手        挑战一下 @对手        @机器人 艾斯比 @对手
```

`决斗` / `挑战` 作为正式指令仍需要唤醒；`签到` / `面板` / `排行` 只按"指令名在开头"
匹配，不会被句中的字眼误触发。

自动签到判断"这条消息会不会有别的回复"用的是同一套匹配，所以光说一句「这个挑战真难」
既不会开打、也不会白白吃掉当天的自动签到。

QQ 官方机器人上 `self_id` 有时是那个被 @ 的**对手**（老插件注释：*Account for QQ
Official events that expose the target At as self_id*），所以判断"这是不是机器人"时要看
消息内容：决斗消息里的 `self_id` 算对手，普通指令里才算机器人。相应地，
`@机器人 艾斯比 @对手` 会优先挑不是 `self_id` 的那个人当对手；如果整条消息只有一个
真实 id 的 @，那就只能当它就是对手（占位 id `qq_official` 例外，那明确代表机器人）。

### 自动签到

白名单群里，**每人每天的第一条消息**会自动完成签到（表情、图片这类没有文字的
消息也算），默认直接回一张签到卡，和老插件的行为一致。

出不出声由 `checkin.auto_checkin_reply` 决定：

| 取值 | 行为 |
| --- | --- |
| `always`（默认） | 每次自动签到都回签到卡，签到立刻可见 |
| `cycle` | 只在连签满 7 / 30 天时出声，平时安静 |
| `silent` | 完全静默，只入库 |

被 `@机器人`、带唤醒前缀或引用机器人的消息**不会**弹自动签到卡（那条消息多半
自带回复），但签到本身照常执行。

无论哪种模式，每次自动签到都会写一条日志，用来确认它到底有没有生效：

```
[astrbot_plugin_funhub] 自动签到 group=123 user=456 streak=3 coins=+130
```

插件加载时也会把生效配置打进日志，便于一眼看出白名单是不是空的：

```
[astrbot_plugin_funhub] 白名单群：123456、aiocqhttp:654321
[astrbot_plugin_funhub] 自动签到：开启（出声策略 always），换日时刻 4:00 Asia/Hong_Kong
```

## 决斗

`/决斗 @某人`（`/挑战`、`/艾斯比`、`/啥比` 同义）。相对老插件做了简化：**三轮随机数改成
一轮**，不看等级、属性、装备，纯运气；**没有冷却**，想打几次打几次。

双方各掷一个 `0~dice_max`（默认 100）的数，谁大谁赢；点数相同就**加赛**，直到分出胜负
—— 没有平局一说。加赛过的回合会排在卡片第二行：

```
决斗 · 龟甲 vs 龟乙
50 : 50 → 90 : 10
龟甲 胜，赢得 200 龟龟币
```

奖惩分两块：**赔币**谁都跑不掉，**禁言只针对主动挑事还输了的那个人**（这样大家不会因为
被动应战而被罚）。

| 情况 | 结果 |
| --- | --- |
| 无论谁输 | 败者赔 `0~stake_max`（默认 500）随机币 × 倍率给胜者 |
| **挑事的人**输了（机器人是管理员） | 额外被禁言 `mute_seconds`（默认 60 秒） |
| 挑事的人输了、而他**已经在禁言里** | 不叠加禁言，本次也免罚（唯一会免掉赔币的情况） |
| **被打的人**输了 | 只赔币，**不会被禁言** |

### 赔付倍率

```
倍率 = 1 + 存款碾压 + 管理员败北
```

* **存款碾压**：败者存款每比胜者多 `rich_step_coins`（默认 500）币，就多赔
  `rich_step_percent`%（默认 10%），最多 `rich_cap_percent`%（默认 50%）。
* **管理员败北**：败者是群主/管理员时（平台不允许禁言他们），**在普通人算出来的倍率上
  再加 0.2 倍**（`admin_percent` 默认 20）—— 这是个**加数，不是固定倍率**：存款相当的
  管理员赔 1.2 倍，又被碾压又被管理员身份才是 1.7 倍。

于是（默认配置下）**普通人最多赔 1.5 倍，管理员最多赔 1.7 倍**。倍率看的是**败者身份**
（管理员根本禁不了言，惩罚一律折成多赔钱），跟谁先挑事无关；只有禁言才看谁先挑事。

| 场景（基础额 200） | 实赔 |
| --- | --- |
| 双方存款相当 | 200 |
| 败者多 1000 | 240（+20%） |
| 败者多 2500 及以上，普通人 | 300（+50% 封顶） |
| 败者是管理员，存款相当 | 240（普通人 200 × 1.2） |
| 败者是管理员且多 2500+ | 340（1.5 + 0.2 = 1.7 倍封顶） |

**赔付按「尽所能」**：上面算出的是**应赔**，实际给多少看败者余额 —— 不够就全给，
穷不豁免，只是给得少；赢家拿到的就是败者真正掏得出的那部分。

禁言在各平台这样实现：

* **aiocqhttp / OneBot**：`get_group_member_info` 查机器人角色、成员角色与禁言状态，
  `set_group_ban` 执行禁言。机器人不是管理员就没有禁言这项；成员角色查得到时，
  明知对方是管理员/群主就干脆不调禁言接口，直接按管理员倍率结算。
* **QQ 官方机器人**：`GET /v2/groups/{group_openid}/bot_state` 取 `member_role`
  判断机器人是不是管理员，`POST /v2/groups/{group_openid}/restrict_chat_setting`
  执行禁言（`op=add` + RFC3339 到期时间）。该接口只能禁言普通成员，群主/管理员
  禁不了。`bot_state` 是白名单接口（错误码 11253），拿不到时角色视为未知：会试一次
  禁言，只有错误明确表示"对方不能被禁言"才按管理员倍率算。

禁言记录同时写进库（`duel_mutes`），用来判断"这个人已经在禁言中" —— 官方机器人
查不到成员级禁言状态，只能靠自己的记录兜底。

```
决斗 · 龟甲 vs 龟乙
10 : 90
龟乙 胜，赢得 340 龟龟币
龟甲 是管理员，赔付 ×1.7
```

## 轮盘

玩法复刻自 [Pallas-Bot 的 `roulette`](https://github.com/PallasBot/Pallas-Bot)（左轮轮盘），
把惩罚换成了"扣龟龟币 + 禁言"，并让参与者有收益。

`/轮盘` 开一局：**开局就定好子弹在第几个弹槽**，所以第几枪响是确定的，一直开就是赌命。
任何人都能 `/开枪`（可以连开），每次开枪：

| 结果 | 效果 |
| --- | --- |
| 空枪 | 第 n 枪 **+`safe_reward + (n-1) × safe_reward_step`**（默认 50 / 100 / 150 …，系统发放） |
| 中弹 | 开枪的人扣 **`hit_penalty`**（默认 500，按「尽所能」）+ 禁言 **1 分钟** |
| 炸膛 | **抽到子弹的那一枪**（子弹在第几个弹槽就第几枪）有 `misfire_percent`（默认 25%）概率炸膛：开枪的人不中弹、白拿 **`misfire_reward`**（默认 500），本局结束 |

越往后开枪越肥，而**该响的那一枪**永远是对赌 —— 75% 中弹掏 500 进小黑屋，25% 炸膛白拿 500 走人。

中弹的扣款**全额**（`share_percent`，默认 100）平分给**本局开过枪的人**：

* **中弹的那个人自己不分** —— 他是掏钱的那个，前面空枪赚到的币也不会被扣回；
* 只发起、没开枪的人不参与分账；
* 分不尽的零头回收，不增发；
* 卡片里**直接写名字**（`龟甲、龟丙 各分到 250 币`），超过 4 个人才收成 `甲、乙、丙、丁 等 6 人`。

**只禁言、不踢人**；不能禁言的角色（群主/管理员）只扣币，与决斗同一套口径。

```
轮盘装填完毕（6 个弹槽 · 1 颗子弹）
空枪 +50 币，之后每枪再多 50
子弹那一枪 25% 概率炸膛，开枪的人白拿 500 币
中弹扣 500 币，全赔给开过枪的人，禁言 1 分钟
发 /开枪 扣扳机
```

```
砰，龟乙 中弹（3 / 6）
扣 500 币，禁言 1 分钟
龟甲、龟丙 各分到 250 币
```

```
炸膛（6 / 6），龟乙 +500 币
```

`/救一下 @某人` 可以把中弹被禁言的人捞出来（`duration=0` 解禁），有 12.5% 概率失败救不成。

### 补一枪

照搬 Pallas-Bot `packages/roulette` 的 `judgment`（原版是「牛牛补一枪」，与「救一下」共用
一个处理函数、只换配置），去掉**踢人模式**与**醉酒联动**，只留「追加禁言 + 卡壳 / 反噬」：

```
/补一枪 @某人     给这个人再补一枪
/补一枪           对名单里所有人各补一枪
```

* 只能补**本局中弹、且还在禁言里**的人 —— 名单由插件自己记（中弹时入册、禁言到期或
  被 `/救一下` 捞走后自动出册），补别人会得到「没有可以补枪的人」；
* `judgment_fail_percent`（默认 12.5%）**卡壳**：什么都不发生（原版的 `fail_prob`）；
* `judgment_backfire_percent`（默认 12.5%）**反噬**：这一枪补到发起者自己头上，
  而且照搬原版 `self_punish_requires_drunk` —— **只有群里喝醉时才会翻车**（见下节）；
* 成功则追加 `judgment_seconds`（默认 60 秒）禁言，**在原有禁言上叠加**；
* 群主 / 管理员禁不了，跳过 —— 原版是直接踢人 / 禁言，我们这里没有踢人。

```
补了一枪，龟乙 又被禁言 1 分钟
卡壳了，这一枪没补上
枪口歪了，龟甲 自己又被禁言 1 分钟
```

**冷却按「人 + 操作」各算一份**：同一个人 `action_cooldown_seconds`（默认 60 秒）内不能再补一次枪，
也不能再救一次人。要点：

* **补枪和救人之间不互斥** —— 甲补完还能马上救；
* **失败的尝试一样要吃冷却**（卡壳、炸膛、救援接口失败都算），不然可以一直刷到成功；
* **多人可以轮流救同一个人**，补枪也是 —— 冷却只锁"谁做的、做的哪件事"；
* 「名单里没人」「点了个不在名单里的人」这种没得做的情况**不吃**冷却；
* 填 `0` 彻底关掉这条规则。

```
① 甲补一枪        → 补了一枪，龟乙 又被禁言 1 分钟
② 甲马上再补      → 刚补过了，再等 1 分钟
③ 甲马上救人      → 龟乙 被捞出来了          ← 不互斥
④ 丙来救同一个人  → 龟乙 被捞出来了          ← 多人可轮流
⑤ 丙马上再救      → 刚救过了，再等 1 分钟
```

### 醉酒联动（跨插件读状态）

原版的「喝酒」是牛牛自己的功能，状态放在 ``BotConfig.drunkenness()``；这里的喝酒在
另一个插件里 —— [astrbot_plugin_repeater](../../astrbot_plugin_repeater) 的
`/喝酒`（`RepeaterEngine.drink`）。它把状态存在**内存**里：

```python
self._drunk_until: dict[str, int]        # "平台:群" → 到期时间戳
def drunk_remaining(group_key, *, now=None) -> int
```

于是龟龟乐园直接从 AstrBot 的插件表（`context.get_all_stars()` → `StarMetadata.star_cls`）
里把那个实例摸出来，调它的 `drunk_remaining("平台:群")` 读状态 —— 两边算 key 的方式
恰好一样（都是 `平台:群`），所以能直接对上。规矩是：

* **只读不写**，不去改对方的状态；
* 对方没装 / 没激活 / 方法改名 / 抛异常 → 一律当**清醒**，绝不因为别人的插件把轮盘带崩；
* 兼容同步、异步以及 `drunkenness()` 这类别的写法（鸭子类型摸一圈）；
* 补一枪的反噬默认只在醉酒时判定（`judgment_backfire_drunk_only`，原版语义）；
  没找到喝酒插件时会打一条 warning 提醒你 —— 想让它清醒时也可能翻车就把这个开关关掉。

启动日志里会写明接没接上：

```
[龟龟乐园] 补一枪：反噬只在醉酒时触发，醉酒状态接的是 astrbot_plugin_repeater
[龟龟乐园] 没找到喝酒插件（astrbot_plugin_repeater），醉酒联动不可用 —— 补一枪永远不会反噬。
```

喝醉之后轮盘上会多出两件事（都可以用配置关掉）：

| 醉酒时的变化 | 配置 |
| --- | --- |
| `/补一枪` 的反噬**只在这时候**才可能触发（清醒时没有风险） | `judgment_backfire_drunk_only` |
| **走火**：中弹的人会连带几个同局开过枪的人一起受罚 —— 中弹者 + 随机 1~N 名开过枪的人，各扣 500、各禁言 1 分钟（原版"醉酒随机命中多人"） | `drunk_extra_max`（默认 2，填 0 关掉） |
| 走火本身还有概率：喝醉只是前提 | `drunk_extra_percent`（默认 **25**；填 100 就是"醉了必走火"，即原版行为） |

多杀的分账口径：**陪罚者之间不互相退款** —— 所有人掏出来的钱按 `share_percent` 分给
**本局开过枪但没中弹**的人；要是所有人都在受罚名单里，这笔钱就回收掉。

```
清醒：砰，龟乙 中弹（3 / 6）
      扣 500 币，禁言 1 分钟
      龟甲、龟丙 各分到 250 币

醉酒：醉酒走火，龟乙、龟甲 一起中弹（3 / 6）
      共扣 550 币（按余额），禁言 1 分钟
      龟丙 分到 550 币
```

赔钱依旧是「尽所能」：陪罚的人只有 50 币就只扣 50（上面例子里的 550 就是这么来的）。

一局的状态放在内存里，按 `平台:群` 隔离，同群同时只有一局；`timeout_seconds`（默认 300 秒）
没人开枪就自动作废 —— 这些和原插件一致。踢人模式没有移植（这里中弹最重就是扣币 + 禁言）。

## 排行

* **等级榜**（`/排行`，默认）：`等级 → 龟龟币存款 → 累计签到`，用来体现导入进来的荣誉等级。
* **龟龟币榜**（`/排行 币`）：按**存款**（当前余额）排，不是累计获得 —— 决斗输掉的钱会真的
  把名次拉下来。
* `/面板` 和 `/排行 @某人` 里的「本群第 N」用的是**龟龟币榜**（存款）名次。

## 数值

所有数值都能在 WebUI 的插件配置里改，下面是默认值。

单次签到所得：

```
基础奖 100
+ 随机奖 0 ~ 50
+ 连签加成 min(连签天数 - 1, 15) × 10        （封顶 +150）
+ 7 天周期奖 300    （连签天数是 7 的倍数时，每 7 天循环一次）
+ 30 天周期奖 1500  （连签天数是 30 的倍数时，每 30 天循环一次，与 7 天周期独立判定、可叠加）
+ 首次签到礼 200    （只有玩家的第一次签到）
```

周期奖励是**循环**的：连签天数一路累加不重置，第 7/14/21/28 天各拿一次 300，
第 30/60/90 天各拿一次 1500；第 210 天两档同时命中。

| 场景 | 单次所得 |
| --- | --- |
| 首次签到 | 300 ~ 350 |
| 连签第 2 天 | 110 ~ 160 |
| 连签第 5 天 | 140 ~ 190 |
| 连签第 7 / 14 / 21 / 28 天 | 460 ~ 510 |
| 连签第 15 ~ 29 天（非周期日） | 240 ~ 290 |
| 连签第 30 / 60 / 90 天 | 1750 ~ 1800 |
| 连签第 210 天 | 2050 ~ 2100 |

连签满 30 天（全勤）约 7700 币。

> 开发备注：`100 币 ≈ 1 元`（10 币 = 1 角）只是当初标定奖励量级的内部口径，
> 玩家可见文案里不会出现元角分换算。

每天按 `checkin.timezone` + `checkin.day_reset_hour` 划界，默认 `Asia/Hong_Kong`
的凌晨 4 点换日：3:59 签到算前一天。断签后连签归 1，但最长连签会保留。

## 等级

等级**只来自导入**，签到不会改变它 —— 老用户的等级是历史荣誉，新玩家从 Lv.1 开始。
配置里的 `levels.max_level` 只用于裁剪导入数据中的异常等级。

因为等级不再成长，`/排行` 默认仍按「等级 → 龟龟币 → 累计签到」排序（保留荣誉感），
想看活跃度用 `/排行 币`。

## 数据导入

输入格式是老插件 `services/export_service.py` 导出的 JSON：

```json
{
  "schema_version": 1,
  "source": "checkin-records",
  "exported_at": "2026-01-05T10:00:00",
  "checkin_day_reset_hour": 4,
  "user_count": 1,
  "checkin_count": 3,
  "users": [
    {
      "user_pk": 1, "platform": "aiocqhttp", "group_id": "123", "user_id": "456",
      "nickname": "龟龟", "level": 12, "exp": 34, "total_exp": 5678, "checkin_total": 3,
      "checkins": [
        {"date": "2026-01-01", "streak_days": 1, "exp_gain": 20, "created_at": "2026-01-01T12:00:00"}
      ]
    }
  ]
}
```

### 插件网页（推荐）

重载插件后，在 WebUI 的插件详情页打开 **数据导入** 页：

1. 把 JSON 拖进页面上传区（也可以先把文件放进 `<插件数据目录>/import/`，再点「刷新」）；
2. 页面给出**预览**：新玩家 / 更新玩家 / 新增签到记录 / 已存在记录 / **将补发多少龟龟币**；
3. 点「确认导入」执行，成功后文件会被归档到 `import/done/`，页面同时显示这次与上次的报告。

页面走 Dashboard 的插件扩展路由，非管理员打不开；后端仍然会校验文件名、大小与内容。

### 命令行

服务器上没有浏览器、或者要批量灌数据时：

```bash
python scripts/import_legacy.py --source levelup_checkin_20260105-100000.json \
    --db data/plugin_data/astrbot_plugin_funhub/funhub.db \
    [--dry-run] [--no-backfill] [--json]
```

不传 `--db` 时会依次尝试 `--data-dir`、`$ASTRBOT_DATA_DIR/plugin_data/astrbot_plugin_funhub/funhub.db`。
退出码：`0` 成功（含被跳过的记录）、`2` 输入或数据库错误、`1` 未预期异常。

### 补发口径

* 逐条历史记录按**当前**签到公式折算：基础奖 + 随机奖期望值（`random_bonus_max // 2`）
  + 该条记录里的连签加成 + 该条记录命中的周期奖励。
* 随机奖取期望值而不是重新掷骰子，保证同一个文件重复导入、换机器导入的结果完全一致。
* **不含首次签到礼**：老用户本来就没有这项。
* 只有**本次新插入**的记录才计账，所以重复导入不会二次发币；不同批次的导出文件里
  新增的日期会各自补发一次。
* `streak_days` 缺失或非法的记录按 0 处理，只补基础奖与随机期望值。
* 老插件的经验一律丢弃，不折算成币。
* 关闭 `import.backfill_coins`（或 CLI 的 `--no-backfill`）时只导入等级与签到记录，不发币。
* 龟龟币的每一次变动都记在 `coin_ledger` 流水里（签到 `checkin`、导入 `import`、
  决斗 `duel_win` / `duel_lose`），因此始终满足：
  `players.coins == SUM(coin_ledger.delta)`、
  `players.total_coins == SUM(正 delta)`（累计获得只增不减，输钱不会让它变小）。

导入只增不改：等级只升不降，签到记录按 `(玩家, 日期)` 去重，重复文件幂等。
白名单外的群数据照常入库，等加进白名单自然生效。

## 数据

每个人的数据按 `(platform, group_id, user_id)` 隔离 —— 与老插件 `users` 表一致，
所以老数据能 1:1 导入，白名单里的多个群互不影响。

数据库落在 AstrBot 的插件数据目录：`data/plugin_data/astrbot_plugin_funhub/funhub.db`。

## 文案规范

玩家可见文案全部集中在 `funhub/messages.py`，维护时请守住这几条：

* 不用任何 emoji；
* 卡片类回复不超过 3 行，签到卡固定 2 行（每命中一个周期追加一行）；
* 语气词克制，整条最多一处，不堆「～」「喵」；
* 不写解释、鼓励、复述性的句子，只给数字和必要标签；
* 数据行统一 `标签 值`，分隔符 ` · `，增量前缀 `+`，没有的行整行省略。

`tests/test_messages.py` 会把这些规则变成断言。

## 安装

插件只依赖 AstrBot 自带的 `aiosqlite`（`requirements.txt` 已声明）。
要求 AstrBot `>= 4.11.2`（`on_waiting_llm_request` 钩子与插件 Pages 支持）。

## 开发

```bash

python scripts/import_legacy.py --source tests/fixtures/legacy_export_sample.json --db /tmp/funhub.db --dry-run
```

`funhub/` 下的模块**不 import astrbot**，因此可以脱离宿主直接测；只有 `main.py`
与宿主打交道（指令注册、自动签到、白名单外的 LLM 拦截、导入页 Web API）。
`tests/test_layering.py` 守住这条边界，`tests/test_main_surface.py` 用桩模块真实导入
`main.py`，把「群里发个表情 → 自动签到 → 回签到卡」这类场景也跑了进去。

## 已知边界

* `/排行币`、`/挑战@某人` 这种连写不匹配指令，参数需要空格分隔。
* 白名单外发 `/签到` 会静默：既不会回复，也不会被默认 LLM 接走。加载时的日志会
  打印当前白名单，白名单为空是「插件没反应」最常见的原因。
* 决斗的禁言依赖平台能力：`aiocqhttp` 与 QQ 官方机器人都支持；其它平台只扣币。
  官方机器人的 `bot_state` 属于白名单接口，拿不到时按"角色未知"处理（试一次禁言，
  失败就只扣币、不给补偿）。
* 导入时如果先用了 `--no-backfill`，这批记录之后不会再补发（补发与否在导入那一刻就定了）。
* Windows 上若 Python 缺 `tzdata`，`Asia/Hong_Kong` 会回退到系统本地时区（日志有 warning）。
